Approov Worker modes and logging

Set APPROOV_MODE to annotate or block. The mode is required.

ModeRequest decisionApproov-Result at the origin
annotateRun checks and forward every protection result.Replace the client value with the Worker's authoritative result, including ERROR results.
blockRun checks and reject if any layer configured as block fails. Continue actions forward failures.Always absent, including on forwarded failures.

Block actions

Require explicit token and message-signing actions. Require a binding action when binding is enabled. Each action is block or continue. Annotation mode accepts none of these action variables.

APPROOV_MODE = "block"
APPROOV_TOKEN_ACTION = "block"
APPROOV_MESSAGE_SIGNING_ACTION = "block"
APPROOV_TOKEN_BINDING_ENABLED = "true"
APPROOV_TOKEN_BINDING_ACTION = "continue"

Message-signature requirements

Set APPROOV_MESSAGE_SIGNING_REQUIRED to install, account, either, or both. An explicit requirement also rejects tokens without signing claims. Every present install/account member must pass.

When unset, retain compatibility with token-only deployments:

ClaimsRequired signatures
NeitherNone
ipkinstall
mskidaccount
BothAt least one; every present member must pass

Use keys only from authenticated, unexpired tokens with a valid audience. Authentic FAIL tokens also receive dependent checks. Malformed claims fail when their member is required or present.

Workers Logs

APPROOV_LOGGING_ENABLED="true" logs every result and the final request decision in either mode. The default is false. Analytics Engine has its own enable switch. Errors remain logged.

{
  "event": "approov.request", "version": 2,
  "mode": "block", "action": "block", "validation": "FAIL",
  "attestation": "FAIL", "responseStatus": 403
}

Summaries include safe layer statuses, individual signature results, selected actions, and duration. Tokens, claims, credentials, bodies, keys, and full URLs are excluded. Debug diagnostics follow the same rule.

Configuration checks

Preflight validates the selected Wrangler configuration and overrides. The Worker also validates its actual bindings during initialization. Invalid configuration refuses startup; later invalid binding changes return HTTP 500 before reaching the origin.
